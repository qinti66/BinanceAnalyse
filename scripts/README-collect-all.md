# 一键采集：`scripts/collect-all.mjs`

在服务器上执行：

```bash
node scripts/collect-all.mjs
```

不依赖本机环境、不需要 GUI、不需要 `HTTPS_PROXY`（服务器直连，`binance-net.mjs` 的现有"有代理走代理、没有就直连"逻辑本来就覆盖这种情况）。

## 做了什么

一条命令依次做三件事，都是对已有脚本的编排，没有引入新的限速/断点逻辑：

1. **实时指标快照**（`collect-indicators.mjs`）：宇宙、行情/资金费率/溢价快照、持仓多空比历史（到期才拉，见 `positions-store.mjs`）。
2. **补齐校准用 1h/4h K 线**到当前最后一根收盘的K线（复用 `backfill-klines.mjs` 的断点续存"只拉尾部"逻辑）。
3. **补齐校准用资金费率历史**到当前（复用 `backfill-funding.mjs` 的断点续存逻辑）。

跑完打印一份人能直接读的汇总：本轮采了什么、有没有失败、持仓历史多久没刷新、**最晚什么时候必须再跑一次**。完整报告落盘在 `data/collect-all-last-report.json`；同时写一份给页面看的小文件 `public/indicators/freshness.json`（持仓历史/K线/资金费率各自最后更新时间，从数据本身读出来的，不是"脚本跑没跑成功"）——`/indicators` 页面会显示这个，超过阈值会高亮。**这是定时任务唯一的监控**：定时任务如果哪天悄悄失败了（403、磁盘满、`logs/` 目录不存在导致命令根本没执行……），没人会去翻日志，但用户每天都会打开这个页面。

## 已知例子：一次装错

用户第一次装 cron 时把 `/path/to/BinanceAnalyse` 占位符原样跑了（没替换成真实路径），导致装了一条不会真正执行的 cron。查的方法很直接：`crontab -l` 看内容对不对，`crontab -l | grep -v '误的那条' | crontab -` 删掉。**装完之后一定要 `crontab -l` 核对一遍，光"装完没报错"不代表命令是对的。**

## 遇到限速/封锁怎么办

**完全手动触发，不自动重试，不提供任何绕过开关。** 任一阶段遇到 403/418/429/451，那个阶段照旧立即停止（沿用各自脚本原有行为），本脚本会在汇总里如实报告"STOPPED"和原因，然后继续下一个独立阶段（比如 K 线那一步被拦不该连累持仓历史那一步）。**没有任何"等一会儿自动重跑"的逻辑**——下次什么时候能再跑、要不要等，由跑这个脚本的人自己判断。

## 如果想加定时任务

这个脚本本身不含调度器（项目里一直的规矩：不引入对着封锁自动重试的机制）。如果想要**定时触发**（而不是自动重试），可以在服务器上加一条 cron：

```cron
# 每 7 天跑一次；日志自己看，遇到 STOPPED 需要人工介入，不会自动重跑
0 3 */7 * * cd /path/to/BinanceAnalyse && node scripts/collect-all.mjs >> logs/collect-all.log 2>&1
```

这条 cron 只是"定时敲这条命令"，遇到限速/封锁该停照样停，不改变脚本本身的任何行为。**是否要装这条 cron，需要用户自己决定并自己在服务器上装**——不由这个脚本自动安装。

⚠️ **`*/7` 在 cron 的"日"字段里不是"每 7 天"，是"每月的 1、8、15、22、29 号"。** 算过实际间隔：1→8→15→22→29 各 7 天，29 号到下月 1 号是 2-3 天，2 月（28 天）22 号到 3 月 1 号正好 7 天——**最大间隔恰好卡在 7 天，没有超过持仓历史要求的 10 天窗口，但这是巧合，不是这个写法本来的语义**。以后如果要改成"真正每 N 天"，得用别的机制（比如 systemd timer 的 `OnUnitActiveSec`，或者脚本自己记录上次运行时间再判断），不要想当然地把 `*/7` 当成"每 7 天"去改数字，改出一个超过 10 天的间隔反而更危险。

## 装完之后务必确认两件事（脚本自己测不出来）

1. **`logs/` 目录存在**：cron 那条命令里的 `>> logs/collect-all.log` 如果 `logs/` 目录不存在会导致整条命令直接失败，而且不会有任何提示——`mkdir -p logs` 补一下就行，`scripts/collect-all.mjs` 的用法示例已经带了这一步。
2. **手动跑一次确认脚本本身能跑通**：`node scripts/collect-all.mjs`，看汇总里有没有 `STOPPED`。**一个从来没有成功执行过的定时任务，效果和没装是一样的，但会让人误以为已经在正常工作。**
