# 特征规格 v1（指标架构的执行契约）

> 本文是 `docs/handoff-probability-panel-v1.md` 第六节的展开。第六节回答"选哪些指标、为什么"，本文回答"每个指标精确怎么算"。
>
> **`lib/indicators/features/registry.ts` 必须逐条实现本文，且在训练开始前冻结。**训练产物里要存本文的版本号，线上打分时版本不匹配直接拒绝出概率。

## 一、六条不可违反的架构规则

### R1 · 唯一实现，训练与线上共用

```ts
export function buildFeatureVector(
  bars: Bar[],          // 主时间框架，最旧在前
  atIndex: number,      // 只允许看 bars[0..atIndex]
  ctx: FeatureContext   // 横截面与环境数据，同样只含 atIndex 时点及之前
): { values: Float64Array; missing: string[]; version: string };
```

训练脚本和 `buildIndicators` **必须调用同一个函数**。禁止在训练侧写"等价实现"——这是 train/serve skew 的唯一来源，而它一旦发生就静默无声：线上喂给模型的不是它训练时见过的东西，但一切看起来都正常。

### R2 · 不允许未归一化的绝对量进入模型

BTC 的 5000 万美元成交额和某个小币的 5 万，不是同一个量纲。所有跨币种汇总训练的特征必须先归一化：

| 原始量 | 归一化方式 |
|---|---|
| 成交额、ATR 等有量纲的 | **相对自身尾随历史的百分位** |
| 价格变动 | **除以 ATR** |
| 资金费率 | **相对自身尾随中位数的 z 分数** |
| 跨币比较 | **横截面排名百分位** |

违反这条的后果不是报错，是模型学会了"BTC 和小币不一样"这个毫无用处的事实。

⚠️ **归一化前必须先对齐量纲（2026-09-20 补）**：上表"价格变动 ÷ ATR"**默认了分子是价格单位**。规格早期版本里 `c1` 的 `(h−l)/c` 与 `c2` 的 `ret1` 其实已经是**比率**，再除以价格单位的 `atr` 得到的是 `1/price` —— **随价格漂移，趋势币上尤其糟**。
**`X / ATR` 只有在 `X` 是价格单位时才无量纲。**分子已是比率时，改用 `atrPct` 作分母。

**`atrPct_24h ≡ atrPct_1h × √24`（写死，不许"改进"）**：它对所有币在所有时点是**同一个常数倍**，会被回归系数整个吸收，跨币归一化完全来自逐币不同的 `atrPct_1h`——所以 √-标度是否精确不影响模型。
但若改用真实 24h/4h bar 算已实现波动，**就不再是常数倍**，会真正改变跨币关系并多一个缺失条件。按 R1，此定义唯一且固定。

### R3 · v1 模型的特征全部是必需特征

线性模型无法在打分时"跳过"一个缺失特征——系数需要重新归一化，而那等于换了一个模型。因此：

- v1 特征集内**任一特征缺失 ⇒ 该币不出概率**，显示"数据不足"
- 训练时也**只用全部特征齐备的样本行**
- 想加"有则更好"的特征，等 P6 做单独的模型变体，不要在 v1 里做插补

⚠️ 这条覆盖交接文档里 `minFeatureCoverage: 0.8` 的写法——v1 的要求是 **1.0**。

### R4 · 区分"没发生"与"无法判断"

这是本项目"缺失就是缺失"原则最容易被搞错的地方。**三态，不是两态**：

| 状态 | 含义 | 取值 |
|---|---|---|
| **没发生** | 区间识别成功，窗口内确实没有扫荡 | `f1 = 0` |
| **没有那个结构** | 数据充足，但价格在走趋势、不存在相干的水平边界 | `f1 = 0`（**真实的市场状态，不是未知**） |
| **无法判断** | bar 数不足、ATR 无效 | `f1 = missing`，该币不出概率 |

⚠️ 本规则的早期版本把第二行归入了"无法判断"，实测导致覆盖率 33.8%。见"区间判别参数"一节。**"没有可识别的区间"不等于"不知道有没有发生扫荡"**——它恰恰说明那个事件确实没发生。

每个特征都必须明确回答这个三分。下表的"缺失条件"列就是答案，且必须通过 **R6** 的检验。

### R5 · 特征必须在线上可算

**训练时能算、线上算不出来的特征，比没用更糟。**按 R3 的规则，一个永远缺失的特征会让**所有币种都不出概率**——面板整体失效，而且失效得很安静。

设计任何特征前先回答：线上采集到的数据够不够算它？

| 线上可用量（每轮采集） | 约束 |
|---|---|
| 1h K 线 **400 根**（P2 起，原 360） | 尾随窗口 ≤ 336；ATR 预热 13 ⇒ 实需 349，余量 51 根 |
| 4h K 线 **400 根**（P2 起全币种采集） | 同上（336 根 4h = 56 天） |
| 1d | 由 4h 聚合，仅 60 根 ⇒ **不足以做百分位类特征** |
| BTC 长历史 | 单独深采（只有一个 symbol，成本可忽略），支撑 `g2` 的 1 年分位。**每轮必备**，见 G 组 |

⚠️ **为什么从 360 提到 400（2026-09-20）**：`d1`/`c1` 需 ATR 预热 13 + 尾随 336 = **349 根**，360 下余量仅 11 根——任何一根缺失该点就缺失。klines 属**权重族**，`limit` 101–500 同为 weight 2，**360 → 400 成本为零**。顺手做掉。

### R6 · 缺失还是 0，取决于"0 会不会说反话"

R4 给出三分类，R6 给出判定它的方法。**判据不是"能不能算出来"，而是：**

> **值 0 说出来的那句话，在这个状态下是不是真的？**

- 0 的语义与真实状态**同向** ⇒ 用 0（哪怕算不出精确值）
- 0 的语义会**反转** ⇒ **必须缺失**（哪怕技术上填得进去）

实例（2026-09-20，干净单边趋势、swing < 4 的场合）：

| 特征 | 0 的含义 | 在强趋势中 | 裁定 |
|---|---|---|---|
| `f1_sweep_reclaim` | "没发生扫荡收回" | 真 | **0** |
| `f3_range_containment` | "价格不尊重任何水平位" | 真 | **0** |
| `f2_trend_state` | "**没有明确趋势**" | **假，且正好说反** | **缺失** |

同一个触发条件（swing < 4）对三个特征给出不同裁定，这不是不一致——**是 R6 在起作用**。

`f2` 的 0 是三分类里的"中性"档；在最强趋势的场合输出"无趋势"比不输出更糟：模型会学到一个反向关联，而且**它看起来像是有效信号**。

`f3 = 0` 是把观察到的状态编码在其自然位置（range 情形下 f3 跨 0.28–0.92，0 落在"最不像区间"那一端，单调、连续、无语义断裂），**不是填补缺失**。代码注释须写明，防止后人"优化"成中位数填充。

⚠️ **P2 待办**：R6 是在 f1/f2 的具体冲突中总结出来的，因此下文特征表的"缺失条件"列是按 R6 之前的思路写的。**必须逐条复核全部特征，找出还有哪些的 0 会说反话。**

训练侧用回填的数年历史，样本充足；**但特征定义必须按线上的窗口上限来设计**，不能按训练侧的富余来设计。

## 二、时间框架与模型变体

### 2.1 为什么不是"所有特征 × 所有周期"

7 个周期 × 18 个特征 = 126 个特征，而有效独立样本只有几千。必然过拟合。

### 2.2 周期架构（2026-09-20 修订）

**向上聚合是免费且精确的，向下拆分才需要真正采集。** 4h K 线 = 4 根 1h 的精确聚合（开=首开、高=最高、低=最低、量=求和），且币安 4h 边界对齐 00:00/04:00/… UTC，与我们整点对齐的 1h 数据分组后**逐根一致**，不是近似。

但线上只采 360 根 1h，聚合成 4h 只有 90 根，**不足以支撑 336 根的百分位窗口**（违反 R5）。两个补法比较：

| 方案 | 额外请求 | 磁盘 | 得到 |
|---|---|---|---|
| 加深 1h 到 1344 根 | +603 | 单轮 96MB → **300MB+** | 4h 窗口 336 根（56 天） |
| **直接采 4h × 360 根（全币种）** ✅ | +603，约 +1200 权重 | **+25%** | 4h 窗口 360 根（**60 天**），且 1d 可免费聚合 |

**采纳后者。**理由：成本低一个数量级；历史更长；顺带得到 1d；4h K 线走便宜的行情族，不碰 `/futures/data/` 的 200 请求/分钟紧张配额。而"1h 不够深"这个担忧本身不成立——线上只给最新一根打分，360 根对所有 1h 特征已够；训练用回填的数年历史，不受此限。

| 周期 | 来源 | 覆盖 | v1 用途 |
|---|---|---|---|
| 1h | 已采集 360 根 | 全部 526 币 | 主特征集 |
| **4h** | **P2 起新采 360 根** | **全部 526 币** | 结构类特征的上层上下文 |
| 1d | 由 4h 聚合（免费精确） | 全部 526 币 | **暂不入 v1**（仅 60 根，不够百分位） |
| 5m / 15m / 30m | 真采，无法从 1h 拆出 | 仅 tier-B 约 60 币 | fine 变体，P6 之后 |

⚠️ **必做的对账测试**：用 1h 聚合出的 4h，与币安直接返回的 4h **逐根比对**，应完全一致。不一致就说明时区对齐或聚合边界有 bug——这类 bug 平时完全静默，却会让训练与线上算出不同的东西。

### 2.3 哪些特征加 4h 版本

划线原则：

- **统计类特征（百分位、z 分数）不加周期** —— 用更长的 1h 窗口几乎等价，没必要多维护一套对齐
- **结构类特征加** —— K 线的高低点定义了结构本身，4h 的区间上下沿和 1h 的根本不是一回事；扫破 4h 区间下沿是比扫破 1h 区间大得多的事件

⚠️ **多周期特征在构造上就是相关的**：4h 那根 K 线**包含**了那 4 根 1h。它们不是独立证据，这和七套体系的陷阱完全相同。所以 4h 版本必须作为**独立特征组**加入并单独测量 ΔBSS——涨了就留，没涨就删，不要因为"多周期共振理论上成立"而保留。

### 2.4 模型变体

| 模型 | 主周期 | 覆盖币种 | 何时做 |
|---|---|---|---|
| **base（v1）** | **1h + 4h** | **全部 526 个** | 现在 |
| fine | 增加 15m / 30m | 仅 tier-B（约 60 个） | P6 之后，单独校准、单独门槛 |

两个预测头（4h / 24h）**共用同一套特征**，只是标签前瞻窗口不同。

### 2.5 尾随窗口统一约定

| 用途 | 窗口 | 说明 |
|---|---|---|
| 百分位 / z 分数的尾随基线 | **336 根**（1h 或 4h 各自的） | 与现有 `volSqueezePct` 一致 |
| beta 估计 | **168 根 1h（7 天）** | 样本足够且对 regime 变化有响应 |
| 资金费率基线 | **90 个结算周期**（8h ⇒ 约 30 天） | |

窗口不足 ⇒ 该特征缺失，**不缩短窗口凑数**。

## 三、v1 特征集（16 个，全部必需、全部可深度校准）

> 记号：`bars[i]` 为主周期 K 线，`i = atIndex`；`atr[i]` 为 ATR14；`pct(x, series)` 为 x 在 series 中的百分位（0–100）；`z(x, series)` 为相对中位数与 IQR 的稳健 z 分数。

### C 组 · 吸收（有人在吃掉卖盘）

| ID | 定义 | 缺失条件 |
|---|---|---|
| `c1_effort_vs_result` | **`pct(qvUsd[i], 尾随336) − pct((h[j]−l[j])/atr[j], 尾随336)`**（分位排名差，并列取 mid-rank）。**高值 = 花了大力气但价格没动** | 尾随窗口不足 336；`atr[i]` 为 null；`qvUsd` 缺失 |
| `c2_sell_absorbed` | `sellRatio[i] × (1 − min(1, \|close_i − close_{i−1}\| / atr[i]))`，其中 `sellRatio = (qvUsd − takerBuyUsd)/qvUsd`；**`qvUsd = 0` 时 `sellRatio = 0`（显式，不许留给 NaN）** | `takerBuyUsd` 或 `qvUsd` 缺失；`atr[i]` 为 null |

⚠️ **`c1`/`c2` 的分母是价格单位的 `atr`，分子也必须是价格单位（2026-09-20 修正）**：早期定义 `range=(h−l)/c` 与 `ret1` 是比率，除以价格单位的 `atr` 得到 `1/price`，**随价格漂移**。改为 `(h[j]−l[j])/atr[j]` 与 `|close_i − close_{i−1}|/atr[i]`。见 R2 的量纲补注。

⚠️ **`c1` 改用分位排名差而非 log-z（2026-09-20 裁定）**：原定义 `z(log(qvUsd))` 在**零成交小时**（冷门币确实会出现）得到 `−∞`。但理由不止零值——**加密成交额极厚尾，log 之后的 sd 本身就不稳**，z 分数站不住。分位排名对零值与厚尾都稳健，且与 `d1`/`d4` 口径一致、自动满足 R2。

C 组是本方案的关键——**它是持仓信号在价格与成交量上的影子**。有人吸筹，即使完全看不到 OI 数据，也会在"量不小但价格不动"上留痕。而量和价都来自 K 线，可回填数年。

### D 组 · 蓄势（波动与成交在收缩）

| ID | 定义 | 缺失条件 |
|---|---|---|
| `d1_vol_squeeze_pct` | `pct(atrPct[i], 尾随336)`。**越低越紧** | 尾随窗口不足 |
| `d2_volume_dryup_pct` | `pct(qvUsd[j] / hourOfDayBaseline[hour(j)], 尾随336)`。基线 = **以 i 为终点的 336 窗口内**、按 **UTC 日内小时**分 24 槽的中位数，**整窗固定一套**（与 `d3` 的 `M` 同逻辑；逐 j 重算需 336 根之外的历史 ⇒ 违反 R5）。含当前 bar 不是前视（bar i 已收盘） | 尾随窗口不足；该槽样本 **< 8**；**该槽基线中位数 = 0**（比值无定义；按 R6 此时 0 会谎称"处于典型水平"） |
| `d3_compression_bars` | 从 i 往回数，连续多少根满足 `atrPct < M`，**其中 `M = median(以 i 为终点的尾随 336)`，是一个常数**，上限 168 | 尾随窗口不足 |
| `d4_vol_squeeze_4h` | 同 `d1`，但在 **4h** 上。多周期压缩共振是真实现象，但与 `d1` 相关，由 ΔBSS 决定去留 | 4h 尾随窗口不足 336 |

⚠️ `d2` 的日内小时基线是**修复既有偏差**，不只是新特征：现有 `volumeRatio`（近 4h ÷ 前 24h 均值）完全忽略了加密市场强烈的日内季节性——亚洲凌晨的"放量"和美盘开盘的"放量"根本不是一回事。

**`d2` 为什么是 hour-of-day 而不是 hour-of-week（2026-09-20 裁定）**：原规格写 hour-of-week（168 槽），但线上只有 336–360 根 1h，**每槽仅 2–3 个样本 < 4 ⇒ 线上恒缺失**；训练侧用多年历史却算得出——这是最坏的一类 **R5 违反：静默的 train/serve skew**。改 24 槽后每槽 14 个样本。下限定 **8**（不是 4）：14 个样本下要求 ≥8 容忍丢 6 根；≥4 等于容忍丢 10 根，那个中位数已不可信。

⚠️ **已知局限 + 预先登记**：hour-of-day 丢掉工作日/周末差异。加密永续周末成交偏低，`d2` 可能产生**周周期的假阳性**。不预先复杂化；**若 P3 中 `d2` 残差呈现周周期，回来加周末控制变量**。

⚠️ `d3` 的参考中位数 **`M` 必须固定为"以 i 为终点的尾随 336 的中位数"**，不是逐根滚动重算。滚动版需 `336+168+13 = 517` 根 > 线上 360，**不可算（R5）**；固定版也是语义上更干净的——一次游程应对着一条固定参考线数，滚动阈值会让参考线在游程内部漂移。
这不是前视：特征在 **i 时刻**求值、只用 i 之前的数据；`M` 取自 `i−336..i` 却应用于 `i−50` 那根不构成前视，因为我们没有声称它在 `i−50` 时可算。

### E 组 · 横截面（独立于大盘的强度）

| ID | 定义 | 缺失条件 |
|---|---|---|
| `e1_rel_btc_24h` | **`(ret24h − β × ret24h(BTC)) / atrPct_24h`**，β = 尾随 168 根对 BTC 收益的 OLS 斜率，裁剪到 [0, 3]；样本不足时 β 缺失（**不默认为 1**） | BTC 数据缺失；β 无法估计；自身 24h 收益缺失；`atrPct_24h` 缺失或为 0 |
| `e2_rel_median_24h` | **`(ret24h − median(全部币种同时点 ret24h)) / atrPct_24h`** | 同时点有效币种 < 50；`atrPct_24h` 缺失或为 0 |
| `e3_ret_rank_pct` | `ret24h` 在同时点全部币种中的排名百分位（0–100），**并列取 mid-rank** | 同 e2 |

⚠️ **`e1`/`e2` 必须除以自身波动（2026-09-20 裁定，修规格错误）**：原定义是**原始收益差**，违反本文件自己的 **R2**。同样 3% 的超额收益，对大盘币是事件、对高波动小币是噪声——不归一化就是把两者当同一件事。`e3` 是排名，天然无量纲，不动。
BTC 自身的 `e1 ≡ 0` 是真值，无需特殊处理。

⚠️ **这组决定了训练集构建方式**：e2/e3 需要同一时点所有币种的数据，因此训练集必须**按时间点横向遍历全部币种**构建，不能按币种逐个构建。这是管线的结构性约束，不是实现细节。

### F 组 · 结构（七套体系里唯一保留进模型的部分）

| ID | 定义 | 缺失条件 |
|---|---|---|
| `f1_sweep_reclaim` | 最近 48 根内是否发生"跌破区间下沿后收回"：`扫破深度/atr × 0.97^(距今根数)`，取最大值；**未发生 = 0（不是缺失）** | 仅 `unavailable`（bars<168 或 ATR 无效）⇒ 缺失；`no_range` ⇒ **0** |
| `f1_occurred` | 二值：`f1 > 0` ⇒ 1，否则 0。**`f1` 有 59.4% 的精确零点，零膨胀是该变量的结构事实**——用"是否发生 + 发生多深"两项表示是标准做法 | 同 `f1`（缺失条件完全一致，覆盖率零成本） |
| `f1_occurred_4h` | 同上，4h | 同 `f1_4h` |
| `f2_up` | 哑变量：确认摆动点呈 HH∧HL ⇒ 1，否则 0 | 168 窗口内确认摆动点 < 4 |
| `f2_down` | 哑变量：确认摆动点呈 LH∧LL ⇒ 1，否则 0 | 同上 |
| `f3_range_containment` | 区间上下沿之间包含 lookback 内收盘价的比例（0–1）。**低包含率+低 ATR = 缓慢漂移的趋势；高包含率+低 ATR = 真正的横盘蓄势**——这两件事对"早期启动"含义相反 | 同 `f1` |
| `f1_sweep_reclaim_4h` | 同 `f1`，但在 **4h** K 线上计算，**sweep 窗口 = 24 根**（非 48）。扫破 4h 区间下沿是量级更大的事件 | 同 `f1`（4h） |
| `f2_up_4h` / `f2_down_4h` | 同 `f2_*`，但在 **4h** 上。经典的上层趋势条件变量 | 4h 确认摆动点 < 4 |

`f1` 就是 SMC 的流动性扫荡 ≡ Wyckoff 的 Spring，**同一个现象，只算一个特征**。
`f3` 与 `d1`/`d3`（ATR 压缩）预期有相关但**不共线**：ATR 压缩量的是逐根波动，包含率量的是价格是否尊重水平边界。共线性检查按 2.3 节处理。
`f2_*` 只作条件/排除用途：已经走出趋势的不该再叫"早期"。
两个 4h 版本与 1h 版本在构造上相关（见 2.3），必须单独测 ΔBSS 决定去留。

⚠️ **`f1` 不乘包含率（2026-09-20，撤回同日早前的裁定）**：早前版本定义为 `… × 包含率`。撤回，两个理由——(1) 它让 `f1` 与 `f3` **按构造共线**；(2) 更根本的是，它把**一个未经验证的交互作用烧进了特征定义**。若该交互是错的，`f1` 被永久污染且**再也无法干净测量**：ΔBSS 会说"f1 没用"，但分不清是 sweep 没用还是乘错了。
两个主效应先各自测干净。**若 P3 显示确有交互需求，再单独加 `f1×f3` 作为第三个特征**——那时它是被测量的假设，而不是被假设的测量。

⚠️ **`f2` 为什么拆成两个哑变量而不是 ±1（2026-09-20 裁定）**：`f2 ∈ {−1,0,+1}` 在**线性模型**里，+1 与 −1 必然得到相反符号的贡献。但我们要的是"**多头趋势和空头趋势都压低早期概率**"——符号特征做不到这件事。
哑变量也**优于 `|f2|`**：`|f2|` 先验强加了多空对称；哑变量允许不对称，也允许模型自己学出对称。参照类 = 两者皆非。

⚠️ **`f2` 的摆动点窗口 = 168**，与 `rangeLookback` 一致。`f1`/`f2`/`f3` 共用同一套摆动点、同一个窗口——这是"共享摆动点来源"那条裁定的本意。

⚠️ **`f1` 的"收回" = 同一根 bar 内低点跌破下沿、收盘收回下沿之上。**多根收回会引入未经测量的参数；同 bar 也是更干净的事件（止损猎杀的典型形态就是一根长下影）。
**预先登记**：若 P3 中 `f1` 的 ΔBSS 接近 0，备选假设是"多根收回"，**只允许在验证折上试一次，不许扫 N**。

⚠️ **sweep 窗口**：1h = 48 根；**4h = 24 根**（按 `48/168 = 0.286` 的比例配 `lookback 84`）。沿用 48 会让 sweep 窗口超过 lookback 的一半，比例失调。

#### 区间边界取簇内极值，不取簇内均值（2026-09-20，定义变更）

**原定义（簇内均值）有构造性缺陷。**实测 W1：**58.1% 的点 `f1 > 0`，中位数仅 0.052**。

问题不在"触发太频繁"，而在**那些小值测的不是市场行为**：下沿取簇内均值时，**成员自己的影线约一半必然低于均值——这是算术保证的**，与价格有没有被猎杀无关。于是近零那一坨是"该摆动低点在其簇内的离散位置"的函数，**是伪装成信号的噪声，比纯噪声更坏**。

```
区间下沿 = 簇内最低的摆动低点
区间上沿 = 簇内最高的摆动高点
```

语义上也更忠实：止损挂在**所有已知低点之下**。在区间中部买入的人，止损同样放在整个区间下方，不是放在均值下方。

**随之而来**：

1. `f3`/包含率上升（边界变宽），`heightAtr` 分布上移（`maxHeightAtr=25` 只会更不吃紧）
2. **T2 测量必须重跑**。冻结参数（mult=2 / tol=0.5 / lookback=168 / touches≥2 / cap=25）**暂时维持**——簇的成员判定逻辑未变，只是簇内取点位置变了。重跑确认 `has_range ≥ 80%` 即参数照旧
3. ⚠️ **验收判据**：重跑后**报告新的 `f1>0` 占比与分位数**，与 58.1% / 0.052 对照。这是本次改动是否奏效的**唯一判据**。不预设目标值（那又成了拍数字）；**若仍 > 50%，说明根因没抓准，回来重议**

#### 验收结果（2026-09-20，通过）

| | 改前 | 改后 |
|---|---|---|
| `f1 > 0` | 58.1% | **40.6%**（判据 < 50%，通过） |
| 中位数 | 0.052 | **0** |
| `0 < f1 ≤ 0.1`（算术噪声区） | — | **仅剩 4.3%** |
| `f1 > 0.5` | 14.4% | **14.0%** |
| `f1 > 1` | 2.7% | **2.6%** |

**上尾几乎不变是成功的标志，不是遗憾。**若右尾也随之缩小，说明连真实信号一起削掉了。只清掉近零那一坨、尾部纹丝不动 ⇒ **证明被清掉的确实是簇内均值造成的算术产物，不是市场行为**。`ranges` 测试中的"干净震荡 `f1≡0`"为此性质提供代码保证。

T2 重测：`has_range` **85.7%**（原 85.3%）、按月 0.877/0.829/0.871、`heightAtr` p10/p50/p90 = 2.07/3.82/8.60、包含率 p10/p50/p90 = 0.30/0.58/0.91。**参数照旧，无需重新冻结。**

#### `f1` 为什么不做阈值化 / 对数化

剩余 40.6% 的非零并非近零噪声（非零部分中位数约 0.35 ATR，p75/p90/p99 = 0.286/0.612/1.307）。风险是**线性模型被大量中值拉低系数 ⇒ ΔBSS≈0 ⇒ 误丢一个其实在尾部有效的特征**。

处理方式必须分清两类事：

- **阈值 / 对数是"关于信号在哪里"的假设** ⇒ 烧进定义就永久不可测（同 `f1×包含率` 的撤回理由）。**不做**
- **零膨胀是变量的结构事实** ⇒ 加 `f1_occurred` 二值项是标准表示，**没有替模型选任何切点**。**做**

**预先登记**：`f1` 的非线性形式（阈值化、对数化）作为 P3 备选假设，**只在验证折上试一次，好坏都记录，不许扫切点**。与"多根收回"并列。

⚠️ **摆动点必须用 `confirmedIndex ≤ atIndex` 的**。ZigZag 最后一段与 k-bar 分型最后 k 根永远不可用——这是本项目最容易踩的前视偏差。

#### F 组的实现裁定（2026-09-20，P1 验收时定）

**摆动点来源**：v1 中 `f1` 与 `f2` **共用 ZigZag(ATR×N)**，不允许一个用 ZigZag 一个用 k=2 分型。理由是一致性——两个特征若建立在不同的结构定义上，它们的相关性与可解释性都无法推理。k=2 分型在 1h 加密数据上触发过密，做不出稳定的区间边界。`fractals()` 保留为原语但 v1 不使用。

**确认延迟必须拆成两半，不要过度延迟**：

| 成分 | 是否有确认延迟 |
|---|---|
| 区间上下沿（来自摆动点） | **有**，必须 `confirmedIndex ≤ atIndex` |
| 扫荡事件本身（跌破 + 收回） | **没有**。收盘价就是收盘价，破了下沿又收回，当时实时可知 |

推论要接受：若一个更好的边界在 `atIndex` 之后才确认，则在 `atIndex` 用的就是当时那个较旧的边界——**这是正确行为，不是缺陷**。

**`premium/discount` 不在 v1 特征集内，完全不做**（不是延后）。

#### 参数敏感性与预登记备选

`has_range` 覆盖率（cap25、触碰≥2；tol = 0.3/0.5/1.0）：

| mult | tol=0.3 | tol=0.5 | tol=1.0 | 跨度 |
|---|---|---|---|---|
| 1.5 | 89.2 | 93.3 | 96.0 | 6.8 |
| **2** | 72.4 | **85.3** | 94.7 | 22.3 |
| 3 | 23.4 | 38.5 | 61.6 | 38.2 |

冻结点在斜坡上而非平台上（tol 0.5→0.3 掉 12 个点）。仍维持 mult=2 / tol=0.5：

1. **参数敏感性 ≠ 时间稳定性。** 前者是"改参数会怎样"，而参数已冻结、不会改；后者是"参数不变、换时段会怎样"，那才是上线后真正暴露的风险。实测按月 `has_range` = 0.874 / 0.825 / 0.866，跨度仅 5 个点
2. **覆盖率是约束不是目标。** 85.3% 已远超门槛；为 93.3% 而选 mult=1.5 是在优化错的东西——1.5 ATR 的反转在 1h 加密数据上偏小，由它构成的边界更不可能是真实的止损聚集，而 `f1` 的全部意义就在那里

**预登记（防止事后钓参数）**：若 P3 中 `f1`/`f3` 的 ΔBSS 接近 0，第一个要检验的假设是"摆动尺度选错了"，预登记备选为 **mult=1.5 / tol=0.5**。该备选**只允许在验证折上试一次，结果无论好坏都如实记录**。**不允许扫描 mult×tol 网格取最优格**——那样拿到的提升是在测试集上过拟合，且事后无人看得出来。

#### 包含率从"门槛"改为"特征"（覆盖率发现驱动的设计变更）

按门槛用法（包含率≥0.6 ∧ 触碰≥2 ∧ cap≤25），只有 **33.8%** 的 (币, 时点) 能产出有效区间。按 R3/R4，这意味着面板最多对约 1/3 的点出概率——与 `earlyCandidate = 0` 同类的失败。

根因不在参数，在**原规格把两件不同的事混成了"缺失"**：

| 情形 | 真实含义 | 处理 |
|---|---|---|
| 数据不够（bar 数不足、swing 不足） | 确实不知道 | **缺失** |
| 数据够，但价格在走趋势、没有相干的水平边界 | **这是一个真实的市场状态**，不是未知 | **值 = 0** |
| 找到边界，窗口内没发生扫荡 | 真实状态 | 值 = 0 |

第二行是关键：*"没有可识别的区间"不等于"不知道有没有发生扫荡"*——它恰恰说明不存在 `f1` 想检测的那种止损聚集边界，所以那个事件确实没发生。

**改法**：

```
三态（f1 / f3）：
  bars < 168  或  ATR 无效/为 0                   ⇒ unavailable  （唯一的缺失）
  bars 充足 ∧ swings < 4                          ⇒ no_range，f1 = 0，f3 = 0
  bars 充足 ∧ swings ≥ 4 ∧ 无相干边界              ⇒ no_range，f1 = 0，f3 = 0
  边界可定 ∧ 上下沿各触碰 ≥ 2 ∧ heightAtr ≤ 25     ⇒ range，照算   → 实测 85.3%

f1 = 扫荡深度/atr × 0.97^(距今) ；未发生 = 0      ← 不乘包含率，见 F 组
f3 = 包含率本身（0–1），独立特征

f2 不适用本三态：swings < 4 ⇒ 缺失（按 R6，0 会说反话）
```

⚠️ `swings < 4` 对 `f1`/`f3` 判 no_range、对 `f2` 判缺失——**同一触发条件、不同裁定**，这是 R6 在起作用，不是不一致。

包含率实测 p10–p90 = **0.28–0.92**，离散度这么大，压成一个是非题是在丢弃信息。覆盖率 33.8% → **85.3%**，同时模型拿到的信息**更多**而非更少。

这条变更由 P1 的测量直接驱动。若按原规格闷头实现，会造出一个三分之二的点空白的面板。**这是"先测量后冻结"这个流程本身的收益。**

#### 联合覆盖率（P3 前必须回答）

R3 要求所有特征齐备才出概率，而**覆盖率是相乘的**：16 个特征各自 95% 可用，联合起来是 `0.95^16 ≈ 44%`。

`f1/f3` 的 85.3% 只是单项。实现完整特征集后**必须报告联合覆盖率**（多少 (币, 时点) 能拿到全部特征）：

- **≥ 60%** → 正常推进
- **< 60%** → 停下，重新审视 R3 是否过严，而不是上线一个大面积空白的面板

⚠️ **早前"联合约 75%"的粗估已作废（2026-09-20）**。R6 复核发现原规格下 `d2` 线上覆盖率是 **0%**（见 D 组），`a3` 还要排除 20 个无周期币与全部非永续。**在 `d2`/`a3`/`d3`/`c1`/`e1`/`e2` 的修正落地前，任何联合覆盖率估计都没有意义。** ≥60% 的门槛不变，等实测。

#### `a3` 的两处实现裁定（2026-09-20）

**(i) 尺度可能为 0。** 实测当前快照 589 个永续里 **128 个（21.7%）当前费率恰等于 0.0001 基准值**，这类币历史极可能是常数 ⇒ `IQR = 0` ⇒ 除零。

> 在 **W1** 上统计全部永续的尾随 30 天 funding IQR（**按 `fundingDaily` 口径归一后**）分布；**下限取非零 IQR 的 p10**。

#### 判据修正 + 冻结值（2026-09-20）

⚠️ **早期版本附加的"clip 率 ≤ 2%"判据已作废——那是一个拍出来的数**（且是在同一段里写下"不许拍"之后拍的）。实测证明它**在数学上不可达**：

在下限**完全不起作用**的最大 IQR 段（≥0.3 %/天），clip 率仍有 **2.08%**——**2% 就是资金费率厚尾自身的水平**。唯一能压到 2% 以下的办法是把下限抬到 p50 以上，而那时一半以上的点 z 已退化成"绝对偏离"，**直接违反 R2**。

根本错误是**用一个数考核两个互不相关的机制**：

| 机制 | 职责 | 正确判据 |
|---|---|---|
| **下限** | 防 IQR≈0 时除零 | 只对**缺乏真实尺度**的点起作用 |
| **±5 clip** | 缩尾，防极值主导线性模型 | 缩尾比例在常规范围（1–5% 属正常） |

**改用语义判据**：下限正确 ⟺ 它只对缺乏真实尺度的点起作用，且那些点的 z 语义正确。W1 实测三种情形全部通过：

| 情形 | 占比 | z | 语义 |
|---|---|---|---|
| IQR ≥ 下限 | 56.84% | 不受下限影响 | ✅ |
| IQR = 0，当前 = 该常数 | 82.55%（零 IQR 内） | 0 | "一直没动，现在也没动" ✅ |
| IQR = 0，当前跳变 | 17.45%（零 IQR 内） | 大 ⇒ clip ±5 | "从不波动的币今天动了"——本就该是极端 ✅ |

```
FUNDING_SCALE_FLOOR = 0.009446   （%/天，W1 全部 359 币 非零 IQR 的 p10）
clip 边界 = ±5
```

⚠️ **为什么从 0.009252 更新为 0.009446（2026-09-21）**：前值是该方法在**不完整样本**（308/359 币，51 币因 WAF 中断缺失）上的输出。补齐后重算 = **+2.09%**。

**冻结的是方法，不是方法在残缺样本上的取值。**任何在更完整样本上的重算都直接替换该常量——**不设"变化多大才更新"的阈值**。架构会话早先"若 p10 明显移动则更新"的措辞本身是错的：它暗示存在一个阈值，而这里不需要阈值。

**一个未兑现的担心（如实记录）**：补进的 51 币含 XRP / TRX / XLM / XMR / TAO / WLD / TRUMP 等大市值币，架构会话曾预期"大市值币费率特征不同、p10 可能实质移动"。**实测只动了 2.09%**，整体分布几乎不变（IQR=0 占比 36.85%→36.88%，clip 率 5.82%→5.67%，a3 覆盖率 100%）。⇒ **资金费率 IQR 的分布在市值维度上相当同质**，该担心不成立。

**clip 率 5.82% 记为诊断量，不作门槛。**

**预先登记**：若 P3 中 `a3` 的 ΔBSS ≈ 0，备选假设为"±5 对厚尾饱和过度"，**备选值 ±10，只在验证折上试一次**。

⚠️ 测量覆盖 308/359 个币（缺字母序 SYN 之后的 51 个，因 WAF 中断）。"IQR 与币名无关"是论证不是测量——**采集恢复后补齐**。

**(ii) 结算周期不统一。** 同一快照里 4h 周期占 **434/589（73.7%）**、8h 仅 131、1h 有 4 个、20 个无周期数据。原定义"90 个结算周期"在 4h 币上只有 15 天、在 8h 币上是 30 天——**同一个特征在不同币上量的是不同长度的历史**。且币安历史上多次改过周期，`fundingRate` 接口不返回周期字段。

改为**按时间定义**（尾随 30 天）+ `fundingDaily` 口径归一。周期**逐行**由相邻 `fundingTime` 差推断，**吸附到 {1h, 2h, 4h, 8h} 中最近的一个；差值偏离任何一个超过 10% ⇒ 丢弃该行**（不猜）。
逐行吸附同时处理"中途改周期"与"漏结算"；用整窗中位数会在币安中途改周期时把半个窗口归一错。

无周期数据的 20 个币 `a3` 缺失——那是真的不知道，符合 R4。（逐行推断下，只要历史行够，这些币**可能反而算得出**，P2 回填后看数据。）

**(iii) 新鲜度（2026-09-20 补，规格原先漏了）**：**最新一次结算不得旧于其自身 2 个周期**，否则 `a3` 缺失。否则会把几天前的费率当作现值——实打实的 bug 源。

⚠️ 逐行推断会丢掉**首行**（无前驱），所以"有效行 ≥ 60"实际需要 **61 行**原始记录。

#### (iv) 周期切换边界的判读——**预登记，下载真值前写定**（2026-09-21）

**现状：这条推断规则从未被真值检验过。**归档源的 `fundingRate` 月度文件**带结算周期列**（API 不返回），可作校验真值（oracle）。但首次校验（ARBUSDT 2025-09）是一整月的常数 8h，**没有周期变化、没有漏结算**，恰好避开推断最易出错的全部场合——89/89 一致应记为**"未检验"，不是"通过"**。

⚠️ **周期变化并不罕见且在加速**：本地 308 币约 4 个月数据里，21 个币发生 30 次（4h→1h 21 次、1h→4h 7 次、8h→1h 2 次）；按月 8 月 3、9 月 5、10 月 6、**11 月 16**。P3 训练要拉多年历史，绝对数量会高一个量级——**在未检验的边界行为上训练多年数据，和在它上面跑 30 行，是两回事。**

**已观察到的边界现象**：`API3USDT` 2025-09-21 08:00 与上一行相隔 **2.99999 小时**——1h→4h 切换时第一个周期被对齐到 4h 边界，只有 3 小时。它既不是 {1,2,4,8} 中任何一个，**也不是漏结算**。现行规则丢弃它。

**两条候选规则**：

| | 规则 |
|---|---|
| **A（现行）** | 逐行 delta 吸附到 {1,2,4,8}h；偏离任一候选 >10% ⇒ 丢弃该行 |
| **B（候选）** | 直接用实际 delta 归一；delta 超出窗口内 delta 中位数的 **[0.5×, 2×]** ⇒ 丢弃 |

规则 B 能容纳切换时的部分周期（3h 落在 4h 中位数的 [2h, 8h] 内），同时仍挡得住漏结算（1h 周期下的 8h 空档 = 8× 中位数 ⇒ 丢弃）。

**预登记的判读（下载真值前写定，不许拿到数据再定）**：

| 归档真值列在该行给出 | 结论 |
|---|---|
| **实际经过时间（3h）** | 该行携带真实信息、不该丢 ⇒ **改用规则 B** |
| **名义新周期（4h）** | 币安自身按新周期记账，吸附更接近真相 ⇒ **保留规则 A** |
| **两者都不是 / 内部不一致** | **停下报架构会话**，不得自行选一个说得通的 |

⚠️ **只看一次，结果指向哪边都如实记录。**不得因为"规则 B 看起来更优雅"而在数据模糊时倒向它。

##### 判读表的三处修订（2026-09-21，**下载前**补）

开发会话在下载前指出三个漏洞，均成立。判读表按下面执行。

**修订一：把"语义问题"与"规则变更"拆开——它们的证据量要求不同**

本地 308 币 4 个月里共 30 次周期变化，但**被规则 A 拒绝的行只有 1 个**（`API3USDT` 那个 3h 行）。若只盯"被拒绝的行"，证据量 n=1，"全体一致"是空话。

但 oracle 对**所有边界行**都做比对，而"真值列是什么语义"是一个**关于数据格式的确定性问题**，不是从分布里抽样——30 个边界行足以回答它。两个问题必须分开：

| 问题 | 证据来源 | 门槛 | 结论 |
|---|---|---|---|
| **真值列的语义是什么** | **全部边界行**（约 30） | 见下方三档 | 记入台账，作为 P3 的依据 |
| **生产规则是否从 A 改 B** | **被拒绝的行** | **≥3 行且语义已判明** | 达不到 ⇒ **保留规则 A**，结论标"提示性"，留到 P3 复核 |

**语义判定的三档（2026-09-21 补，下载后未读取前定）**：

| 一致的语义事件数 | 结论 |
|---|---|
| **≥10** | **判明**，记台账作 P3 依据 |
| **3–9** | **提示性**——记录观察到的模式与计数，不作判明、不改任何东西，P3 复核 |
| **<3 或模式混合** | `untested` / `escalate` |

设三档而非二值，是为了**不丢弃 9 个一致观察所携带的信息**，同时也消除"再多拿几个文件去凑够 10"的动机。

🚫 **禁止为跨过门槛而扩大样本（关闭分叉路径）**：本次决策的读取范围**在读取前固定**为「批次 2 的 12 个文件 + ARBUSDT 探测文件」。
**若事件数落在 3–9，结论即为"提示性"，不得改用批次 1 的 51 币去补足事件数。**批次 1（归档同样带周期列）只作**独立复现**，在本次决策记录之后单独读取并明确标注，不参与本次决策。

⚠️ **当前必然达不到规则变更的门槛（只有 1 个被拒绝行），这是预期结果，不是失败。**改与不改在当前数据上只影响 55,000 行里的 1 行——**代价几乎为零，而 P3 时会有多得多的被拒绝行**。此刻要拿的是语义结论，不是规则变更。

**修订二：非拒绝行的不一致 ⇒ escalate，且不得为了对上而调参**

判读表原先只覆盖被拒绝的行。若真值列语义是"该时刻生效的周期"而推断的是"以该行结束的那个周期的长度"，则**每次切换都会在非拒绝行上产生错位**。

> 非拒绝行出现任何不一致 ⇒ **视为语义/实现问题，escalate**。

⚠️ **允许"学到真值列的语义约定"，禁止"调参数去提高与这 12 个文件的一致率"。**前者是弄清正确答案，后者是对 12 个文件过拟合——而生产路径根本拿不到真值列。

**修订三：第四种形态（真值列滞后一行 = 等于旧周期）单独标注**

若 3h 行上真值列写的既不是 3 也不是 4，而是**旧周期**，按表落进 escalate——但它是**系统性滞后**（对所有切换都成立），与"内部不一致"是不同的失效模式。

> 报告中单独标出"**与旧周期相等**"这一类，不得混入泛泛的 escalate。

⚠️ 若该形态成立，它本身就是一个**有信息的语义结论**（"该列记的是产生这笔结算的那个周期"），不是失败。按修订一记入台账，仍不触发规则变更。

##### 读取结果与真正的发现（2026-09-21，一次读取，已记台账 T15/T16）

**预登记判决：`escalate`。**15 个语义事件中 13 个 `(旧,新)`、2 个 `(新,新)`，模式混合；非拒绝行 2 处不一致。按预登记**未改任何规则、未调任何参数**，生产仍是规则 A。

**但记录判决之后的事后观察，比预登记的问题重要得多：**

###### 发现：费率按**名义周期**报价，而非按实际经过时间

基准费率 = 每 8h 0.01% = **0.00125 %/名义小时**。12 个文件里三种周期（1h n=4469、4h n=852、8h n=113）的"每名义小时费率"**众数全部是 0.00125 %/h**。

三个切换行（FUSDT 11-06 04:00、MYXUSDT 09-20 12:00、API3USDT 09-21 08:00）的费率均为 **0.0050%（4h 基准）**，尽管与上一行只隔 **1h / 1h / 3h**。

```
daily = 费率 × 24 / 名义周期        ← 正确
daily = 费率 × 24 / 实际间隔        ← 错误
```

⇒ **规则 A 与规则 B 都用实际间隔，所以两者都是错的。**预登记问的"A 还是 B"是一个**错误的问题**，正确答案是"都不是"。

归档列的真实语义 = **该次结算时生效的名义周期**。三种对齐形态（切换落在 4h 行上 / 新周期首次结算恰好落在整点只隔 1h / 只隔 3h）全部符合这一条。

###### 名义周期在切换边界上**不可从时间戳恢复**

它既不总等于前一间隔（新周期首结算只隔 1h 却是 4h），也不总等于后一间隔（最后一个旧行）。**这不是推断算法的 bug，是信息本身不在时间戳里。**

###### 裁定：不可知 ⇒ 缺失（R4 / R6），不是"换一条更好的估计规则"

> **前一间隔与后一间隔（吸附后）不相等的行，以及被规则 A 拒绝的行 ⇒ 该行丢弃。**

⚠️ **这不是采纳一条事后提出的优化规则，因此不需要新数据来验证。**区别是决定性的：

| | 性质 | 验证负担 |
|---|---|---|
| "有更好的办法**估计**名义周期" | 性能主张 | **必须**在未读过的数据上预登记验证 |
| "此处名义周期**不可知**，按缺失处理" | **拒绝**主张 | 无需——代价有界（每次切换丢 1–2 行 / 约 180 行窗口），且无论真相如何都不会更糟 |

检出判据（前后间隔不等）是"该行位于切换边界"的**逻辑刻画**，不是拟合出来的阈值；漏结算同样触发它，而漏结算同样是不可信的行——**误判方向也是安全的**。

⚠️ **为什么值得修（影响虽小但失效是大的）**：切换邻接行仅占 0.014%（359 币 221,655 行中 31 行）。但若**当前行**恰是切换行，该币此刻的 `daily` 会偏 **4 倍**，a3 随之严重失真。按 526 币逐小时打分估算，全库约每天 1–2 次。**罕见、但每次都错得很大，而且无声。**

⚠️ **留作 P3 预登记**：本判据的**漏检率**（未被捕获的边界行）需在多年历史上验证。届时切换事件数高一个量级，无需额外下载。

###### 预登记设计本身的缺陷（如实记录，不回溯修改）

三分类 `(旧,新)/(旧,旧)/(新,新)` 隐含假设了"归档列记录某种**经过周期**"。实际语义是"**名义周期**"，它在不同对齐下会落进不同模式——`(新,新)` 那两个事件其实与 `(旧,新)` 语义一致，是**同一语义被拆成了两个模式**。

⚠️ **本次读取的 `escalate` 判决按原样保留，不做事后重新解释。**分类法的修订属于**新的预登记**，只能用于新数据。

> **教训：预登记防的是"自欺"，防不了"问错问题"。**本次预登记严格执行并得出了诚实的 `escalate`，而真正的答案来自记录之后的观察。两者都要有——先按预登记如实结案，再让事后观察以事后观察的身份进入台账。

⚠️ **归档的周期列只作校验，永不作特征来源**：线上采集走 API、API 无此列，若训练用真值列而线上用推断，即构成 train/serve skew（R1）——而推断算法本就是为避免这件事才设计的。

现状缺陷：现有逻辑用绝对阈值（`fundingLag ≥ 0.08` 打 0.85 折），但同一个费率数值对 BTC 和对某个小币含义完全不同。`a3` 取代它。

## 五、共线性预期（训练时必须检查）

已知会高度相关的组合，训练前就该预期到：

|---|---|

## 六、实现顺序建议

1. **G 组 + E 组**（横截面与环境）—— 最便宜，且 `e1` 提供的 beta 控制让后面所有特征的评估变诚实。没有它，你分不清"这个币要动了"和"整个市场要动了"
2. **C 组 + D 组**（吸收与蓄势）—— 纯 K 线，可深度回填
3. **A3**（费率 z 分数）—— 需要先接资金费率历史
4. **F 组**（结构）—— 依赖 P1 的摆动点原语
5. **A/B 剩余**（持仓）—— 只做展示，等历史积累

每组加入后重跑评估、记录 ΔBSS 进台账 `docs/calibration-log-v1.md`。**一组特征如果加进去 Brier 技能分没有可测量的提升，就删掉它，不要因为"理论上应该有用"而保留。**

## 七、标签与成本（2026-09-20 冻结）

### 障碍宽度 `k`：√ 标度，单一自由参数

实测（T7，W1，20 币）发现**单一的 `k` 服务不了两个窗口**——障碍按 1h ATR 设，24 根 bar 的走动范围必然远大于 1 个 1h ATR。这是构造上的必然，规格早期版本写"k 暂定 1.0"时默认它通用，是疏漏。

```
k_h = 1.0 × √(h / 4)
  4h  ⇒ 1.0
  24h ⇒ √6 ≈ 2.449
```

**采 √ 标度的理由是自由度，不是精度**：独立设两个 `k` 是两个自由参数、两次钓鱼机会。而 √6 **自己落进了实测合格区间 [2, 3] 的中段**——弱但真实的验证，它没有被强行凑进去。将来增加窗口也不必重新测。

`k_base = 1.0` 由数据定：4h 上 `k=0.5` flat 仅 7%（不合格）、`k=1.5` flat 62.7%（不合格），**1.0 是测过的值里唯一通过的**。

⚠️ 合格判据：三类各自占比 ∈ **[15%, 60%]**。
⚠️ **4h 的合格区间未细扫**（只测 0.5/1.0/1.5），故 1.0 是"测过的合格值"而非"最优值"。**我们不找最优，找的是合格且不钓鱼。**

### 往返成本

```
roundTripCost = 2×0.05%（吃单手续费） + 点差 + 2×0.05%（滑点）
              = 0.20% + 点差
```

⚠️ **不扣成本的标签会造出纸面赚钱、实盘亏损的模型。**这是回测自欺最常见的形式。

| 成分 | 来源 | 偏向 |
|---|---|---|
| 手续费 | 币安公开费率，**确定值** | — |
| 点差 | **用当前快照点差代替整个历史窗口**（历史无点差数据） | **偏乐观**（历史流动性更差、点差更宽） |
| 滑点 | **每边 0.05%，保守假设，非测量值** | **偏悲观** |

两个偏向方向相反、部分抵消，但**不得声称它们精确抵消**——我们不知道。

点差代用品优于固定常数，因为它至少保留了币种间的流动性差异（主要变差来源）。

**必须猜的时候，往对自己不利的方向猜。**

**预先登记敏感性检查**：滑点取 0.02% / 0.05% / 0.10% 三档，报告标签分布与 BSS。要知道结论对这个猜测有多敏感，而不是假装它精确。

### 同 bar 双触

判为**不利方向**（down）。合格 `k` 下仅占 0.1–0.4%，影响可忽略。不要用收盘价猜触发顺序——没有 tick 数据。

### 门槛阈值的两种类别

真正的罪不是"用了判断值"，而是**把判断值伪装成测量值**：

| 类别 | 例子 | 规则 |
|---|---|---|
| **性能阈值**（多好才算好） | BSS 门槛 | **绝不能拍**，必须对着实测随机特征基线比 |
| **充分性阈值**（证据够不够） | 折数、样本数、跨度 | **可以是判断，但必须标明是判断** |

- `minEffectiveN` **派生**，不写死：`20 × 自由参数数`，自由参数数 = `(类别数−1) × (特征数+1)`。特征集变动时自动跟随
- **测试折样本量单列**，绑定 ECE 分箱要求：`≥50/箱 × ≥5 箱 = ≥250 有效测试样本`，且任一类别为 0 即失败
- `minFolds = 3`、`minTestSpanDays = 60` — **判断值，非测量值**，代码注释须写明

### isotonic 校准：暂缓 + 预先登记

现在不做——还不知道模型有无 skill，先建校准层本末倒置，且需要单独校准折会复杂化 walk-forward。

> 若门槛**仅因 ECE 不过**而 BSS 与残差 BSS 都通过 ⇒ 是正则化收缩导致的校准偏移，此时才上 Platt/isotonic（**在验证折上拟合，绝不用测试折**）。
> 若 BSS 本身 ≈ 0 ⇒ 校准无意义，不做。

顺序：**先证明有信息，再谈把信息表达准。**
